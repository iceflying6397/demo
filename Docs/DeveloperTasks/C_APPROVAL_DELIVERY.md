# 开发者 C · 发送审批交付说明

## 已实现页面

审批首页有「待审批／已发送」两组，以及待处理、稍后、五种执行状态筛选。待审批卡片可改比例草稿、保存、取消、调整、确认、稍后和拒绝。调整页可换人群、换方案、单组／双组、恢复推荐。确认页核对已保存配置和版本，最终按钮是「确认并模拟发送」。结果页展示快照、人数、重试和数据状态。另有重试确认、处理记录和记录详情。

发送全程是本地模拟。首页底部的「演示控制」和结果页的推进按钮都标明不是生产操作。

## 共享改动

- `DemoSession`：App 根创建一次，审批页用环境读取。首页仍是 `init(store:)`。
- `ApprovalTask` 增加来源、推荐比例、触达状态、规则 ID 和周期键。配置字段改为可变，任务对象仍整体保存在会话里。
- 新增快照、批次、处理记录、规则生成入口 `createPendingTask(request:)`，以及给 D 的 `touchSummaries()`。
- 人群 03／04／05 和版本档案只在会话中，不改 `MockDataStore` 的原始两个人群、两个方案和历史统计。

## 构建

命令使用仓库根目录、`DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`、generic iOS Simulator、Debug、`CODE_SIGNING_ALLOWED=NO`。

结果：`BUILD SUCCEEDED`（arm64 与 x86_64）。唯一警告仍是本 Demo 不提供 App Intents。本机 `xcrun simctl list runtimes` 为空，未能安装或点击运行。

## 建议演示路径

1. 打开发送审批，核对任务 01 的 2,000 人、30%／70%、600／1,400。
2. 把 A 改成 50 后点取消草稿，再改成 50 并保存。
3. 进入确认，点「确认并模拟发送」。到结果页先推进开始，再把预设改成部分失败后推进结束。
4. 打开重试，先取消一次，再确认全部补发成功，然后推进结束。成功人数应为 2,000。
5. 打开数据 Tab，历史 8.40% 样本仍在。回到审批，用演示控制重置。

版本、资源失效、生日规则、五种状态和空列表都在首页「演示控制」里。

## 已知限制

- 没有客户名单，失败范围是分组上的合计人数，不是真实去重。
- 执行步骤由演示按钮推进，没有后台计时器、随机失败或重试上限。
- 资源有效性是会话里的固定标记，参考日为 2026/10/11。审批页不能新增店铺资源。
- 人群、方案、数据三个页面还没有改成读写 `DemoSession`。审批里发布的新版本不会出现在人群页或方案页。统一重置目前只恢复审批会话。
- 跨 Tab 不打开数据页，只提示到「数据」Tab 查看历史样本。
- 未做真机、iOS 17 运行时、大字体和窄屏的人工点击验收。
